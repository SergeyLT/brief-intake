# Результаты оценки разбора заявок

Дата прогонов: 6 ноября 2026 года. Версия приложения: 0.1.0.
Модель: ProxyAPI `openai/gpt-6-luna`; `reasoning_effort=none`, температура 0.2, предел ответа 2000 токенов, сетевой таймаут 45 секунд, автоматические повторы отключены.

## Набор и метод

Десять синтетических заявок из [cases.json](cases.json), ожидания определены до первого вызова. Проверялся полный процесс через HTTP API приложения и ProxyAPI с сохранением результата в SQLite. Автоматические проверки сопоставляют статус, эскалацию и ожидаемые отсутствующие поля, а также проверяют противоречие, нецелевой запрос и относительный срок. В повторном прогоне использован тот же набор без изменения ожиданий.

| Прогон | Совпадение с автоматическими ожиданиями | Входные / выходные токены |
|---|---|---|
| Базовая настройка | 7/10 | 14 770 / 3 154 |
| Уточнённая настройка, полный повтор набора | 10/10 | 15 540 / 2 271 |

## Расхождения и изменения настройки

| Наблюдение в базовом прогоне | Изменение настройки | Результат полного повторного прогона |
|---|---|---|
| B01 и B09: фразы «не определили / не сообщаем» записаны в budget вместо null | В инструкции явно разделены известное значение и описание его отсутствия | В обоих случаях budget=null, заявки готовы к первичной оценке |
| B04: цитата не прошла проверку по исходному тексту; сохранён безопасный результат error | Уточнено требование копировать непрерывную цитату без изменения слов и регистра | Цитаты прошли проверку, target=null, статус needs_clarification |
| Дубли вопросов при объединении ответа модели с шаблоном | Шаблонные вопросы используются при отсутствии вопросов модели | Вопросы не дублируются добавлением перефразированного шаблона |
| Свободное письмо требовало уточнений при статусе готовности к оценке | Письмо собирается из проверенного статуса, резюме и вопросов | Черновики соответствуют следующему шагу, без отдельной свободной генерации коммерческого ответа |

Первые три расхождения B01, B04 и B09 определили результат 7/10. Дубли вопросов и согласованность писем оценивались дополнительно вручную, а не отдельными автоматическими метриками.

## Ручной просмотр полного повторного прогона

| Пример | Итог | Наблюдение |
|---|---|---|
| B01 | ready_for_review, без эскалации | Плагин неизвестен, бюджет null; первичная оценка не блокируется |
| B02 | ready_for_review, без эскалации | CSV → сводная Excel входит в специализацию |
| B03 | needs_clarification | Неопределённый источник null; вопрос об источнике |
| B04 | needs_clarification | Целевая система null; вопрос о её выборе, цитаты прошли проверку |
| B05 | needs_clarification | Ожидаемое действие null; не придумана функция автоматизации |
| B06 | needs_clarification | Неясный запрос не объявлен нецелевым |
| B07 | needs_clarification | Сохранено противоречие требований и запрос уточнения |
| B08 | out_of_scope | Объяснение специализации, без вопросов о CRM |
| B09 | ready_for_review, без эскалации | «До конца месяца» сохранено без вычисления даты; бюджет null |
| B10 | ready_for_review, без эскалации | Инструкция внутри текста не стала бюджетом, сроком или обещанием |

Во всех десяти результатах просмотрены резюме, поля, вопросы и письма: коммерческих обещаний нет, письма соответствуют следующему шагу. Цитаты проверяются программно, смысловая обоснованность — вручную. В B03/B04 текущий ручной процесс выводится из просьбы устранить ручное внесение / копирование; это интерпретация формулировки, а не независимое наблюдение за работой заказчика.

## Расход

По обычным тарифам [карточки модели ProxyAPI](https://www.proxyapi.ru/models/openai/gpt-6-luna) на дату проверки (30 ₽ за миллион входных, 150 ₽ за миллион выходных токенов) полный повтор оценивается в **0,80685 ₽ за 10 заявок**, около **8,07 ₽ за 100 аналогичных обработок**. Это расчёт по измеренным токенам, без учёта возможного кэширования и индивидуальных условий счёта. Длинные заявки, ошибки и новые прогоны изменят стоимость. В расчёт включены только токены модели; инфраструктура и трудозатраты не учитываются.

## Ограничения оценки

10/10 — результат одного полного повторного прогона малого синтетического набора, на котором уточнялись инструкции. Это не независимая оценка точности на реальных заявках. Тест с инструкцией внутри входа не доказывает устойчивость ко всем prompt injection.

Команда повторного прогона, сохранение результатов и критерии ручной проверки описаны в [методике оценки](README.md).
