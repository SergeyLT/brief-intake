# Оценка качества разбора

В [cases.json](cases.json) находятся 10 синтетических заявок. Ожидания статуса, эскалации и отсутствующих полей зафиксированы до живого прогона. Набор включает полный и неполный бриф, обработку CSV, противоречие, нецелевой запрос, относительный срок и попытку изменить инструкции модели.

Обычный pytest не вызывает модель. Ручной прогон через запущенное приложение расходует квоту и оплачиваемые токены:

```sh
docker compose exec -T api python -m brief_intake.evaluate --base-url http://127.0.0.1:8000 --cases /app/evals/cases.json --output /data/output/evaluation.json
```

Команда использует ключ приложения из окружения контейнера. Результат остаётся в постоянном томе; для копирования создайте локальную папку `output/`, затем выполните:

```sh
docker compose cp api:/data/output/evaluation.json output/evaluation.json
```

Для Python-окружения команда `python -m brief_intake.evaluate` ожидает `BRIEF_API_KEY` в окружении и по умолчанию сохраняет результат в `output/evaluation.json`. `.env` не загружается самим Python автоматически.

Каждый новый прогон использует новые идентификаторы операций и повторно вызывает модель. Ошибки и расхождения дают ненулевой код выхода; результаты сохраняются после каждого случая. Не исправляйте ожидания под полученные ответы. После изменения общих правил повторите весь набор и сохраните результаты обоих прогонов в отдельных файлах.

Автоматическая оценка проверяет бизнес-статус, эскалацию, ожидаемые null, наличие противоречия, объяснение нецелевого запроса и сохранение относительного срока. Ручная проверка обязательна: фактическая обоснованность summary и полей, релевантность вопросов, отсутствие коммерческих обещаний, соблюдение границ специализации и устойчивость к инструкции внутри входа.

Цитата подтверждает наличие текста, но не доказывает верность его интерпретации. Малый синтетический набор не измеряет точность на реальном потоке. Сопоставление прогонов, изменения настройки и ручная проверка описаны в [результатах оценки](report.md).
